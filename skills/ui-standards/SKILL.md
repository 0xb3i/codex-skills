# 可视化界面规范

本技能是可视化产物的共同约束，不替代具体平台、文档或前端技能，也不将局部优化扩大为整体重设计。以实际产物是否可视化判断触发，不以是否编写前端代码判断。

## Let UI self-explain

- 优先用准确的名称、控件、布局、图例和状态表达含义；这些已经表达清楚时，不再添加小字、操作教程或描述性语言重复解释。
- 不惯性增加整块“统计口径”“使用说明”或实现逻辑说明。必要差异先放进指标名、轴标签或图例；只有仍容易误解、且误解会影响判断时，才在相关图表或控件附近放最短说明，不集中堆在页面末尾。
- 保留模拟数据标记、单位、时间范围等影响判断的必要事实，并避免重复。减少的是辅助解释，不是用户要求的正文、图注或必要业务内容。
- 资源导航先区分站点、栏目与单篇内容的层级，再选一致的分类维度；博客、文档、代码仓库不能仅因主题相近而混成同级列表。重要总入口应可直接访问，其子栏目按真实归属组织；精选文章另设阅读区，搜索结果也保留父子关系。

## 图表先保证用户能看懂

- 先明确图表要帮助用户做什么判断，再检查真实数据分布、极值与量级差；根据用户能否读出关键差异选择表达方式。
- 极值或量级差使多数数据挤在轴线附近、难以区分时，调整尺度、分面、拆分系列或更换图表；选法服务于要传达的判断，不让少量极值掩盖主要变化。
- 不为美观截断或隐藏数据，不使用无标识双轴，不制造误导性比例；特殊尺度须清楚标识，拆开的极值仍须可追溯。
- 总览中的类别或排名过多、长尾信息拉长页面时，默认展示适量 Top K，将余项明确汇总并提供展开全部；图形、列表、总额与占比保持同一口径，聚合项不得冒充真实类别参与筛选，当前选中的长尾类别仍须可见。
- 先保证准确、易读，再考虑美观；在桌面实际呈现中验证多数数据的差异可辨、极值仍可查看，不能只检查图表是否成功渲染。

## 配色

- 用户未另行指定时，可控界面、卡片和数据图表默认不使用蓝色或紫色，包括单个数据系列、强调色及渐变。
- 根据现有产品和信息含义选择颜色，例如中性色配少量绿、橙等强调色；不把某一替代色板固定成所有产物的新模板。颜色用于区分数据或状态，不用于制造装饰。
- 对飞书等第三方平台，修改可配置的内容与图表样式；不可控的系统导航、品牌标识和平台样式不通过侵入式修改强行改色。

## 控件一致性

- 可控界面的所有控件（如下拉选择、日期选择、复选框）在收起、展开、选中和禁用等状态都应统一到产品设计系统；优先复用已有、可主题化的成熟控件，不能只美化外壳而露出脱离风格的系统菜单或日期弹层。
- 可以保留原生 DOM 语义和表单机制；定制可见外观时保留键盘操作、可见焦点、标签关联与校验行为。
- 高频、可撤销的本地录入（如一句话记账），识别明确并通过校验后直接保存，不默认插入二次确认；成功后反馈关键结果并提供撤销与详情修正。识别有歧义、校验或保存失败时保留输入，就地提示补充或重试；此规则不适用于支付等有不可逆影响的操作。
- 与筛选结果绑定的数量和角标应与列表共用筛选规则；分类计数按公共筛选范围计算，避免被当前分类自身缩小。验收组合筛选、空结果和分类切换，保留当前零值筛选的可识别状态。
- 同一弹窗或抽屉切换标签时，默认保持外框尺寸、内边距和公共工具栏位置稳定；共享控件使用同一套布局规则。验收需连续来回切换，不能只分别检查各标签的静态截图。

## 卡片

- 尽量不用在矩形卡片侧边或顶部加粗彩色边条的装饰样式，也不通过把色条换到另一侧来规避。
- 用间距、对齐、标题层级和必要的常规细边框组织内容；不因此禁止所有卡片，也不把业务所需的状态指示误当作纯装饰。

## 执行与验收

- 先查看当前真实界面或渲染结果，保留任务范围外的内容与行为，再应用以上规则。
- 默认在桌面端检查实际呈现：说明是否重复、必要事实是否仍可辨认、可控区域是否残留蓝紫配色或装饰性粗色条；涉及控件时实际打开下拉菜单、日期弹层等展开态，核验样式一致性与键盘、焦点及校验行为。只修检查发现的实际问题。
- 按用户已有授权交付到原在线入口，并核验实际页面；版本管理与界面展示遵循用户和项目约定。
