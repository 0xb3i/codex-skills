# 低频副作用流程的静态契约演练

当真实验证会创建工单、发消息、发版、审批、扣费、删除数据，或因频率低、成本高而不适合反复触发时，优先从一次真实只读观察或已发生流程中提炼最小、脱敏的静态契约页面/fixture：

1. 只保留实现依赖的稳定语义，例如节点文本、角色、状态 class、层级关系、可操作属性和必要 URL 形状；不要复制账号、Cookie、Storage、认证头、业务正文或个人数据。
2. 同时构造正确目标与高风险干扰项，例如容器内“全量”和页面 banner“全量发布”，验证选择范围、精确文本、唯一候选和误点击计数。
3. 用 synthetic click counter、幂等标记和重复调用验证写操作最多发生一次；覆盖成功、等待、失败、无候选、多候选、隐藏/禁用候选和页面未 hydration 等关键状态。
4. fixture 只服务测试，不得进入生产选择器或运行时 fallback；生产路径仍必须从真实 DOM/接口读取状态，不能用 fixture、mock 或假数据伪造成功。
5. 测试使用隔离页面或本地临时服务，不向真实系统提交；完成后关闭自建页面、停止临时服务并删除临时文件。
6. 静态演练验证的是页面契约和状态机，不等同于真实端到端通过；下一次正常业务任务中顺带验收真实写链路，不为测试额外制造副作用。
