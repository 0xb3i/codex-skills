# 评测维护与手动回归

## 运行边界

新加入且尚无行为运行结果的案例，题面与预期固定后默认运行一轮简介路由与执行效果，建立可查看的首次基线；用户明确要求“只保存”“先别跑”时暂存并标记未运行。新增题的首次运行只覆盖新增案例，不顺带重跑旧题。已有题回归仅在用户明确要求“跑回归”“评测这些场景”等时执行，不因技能修改、普通错误记录或时间安排自动启动，也不创建定时任务。格式校验、路径检查和确定性工具测试不算模型评测。

沿用原生子智能体执行，脚本只负责准备输入与收集文件证据，不接模型 API。模型与运行环境记录实际值，不猜测。原生子智能体共享文件系统，以下是流程隔离，不是强制安全沙箱；需要真实发布、通信或收费才能验证的场景，应改用脱敏 fixture，无法替代的部分标记未测。

## 案例的唯一来源

每个目标技能维护一份 `evals/cases.json`，原题与预期均存这里，不把题库复制到技能正文或 AGENTS.md。案例被评测时，执行者只能看到去掉答案的输入；原始案例文件仅供出题者和裁判读取。

- `skill`：所属技能名称；`cases`：案例列表。
- `id`：稳定且唯一的案例标识，便于复测失败项。
- `origin`：`kind` 为 `user_feedback` 或 `constructed`，`note` 简述来源；不得把构造场景当作真实故障。
- `prompt`、`context`：原始请求和完成它所需的事实，包括指令位置映射及已核实的工具行为；不夹带诊断、修复方案或通过条件。
- `fixtures`：相对测试工作区的文件路径与初始文本；不能使用绝对路径或 `..`，不放密钥、个人资料、真实业务快照。
- `expected.trigger`：`required`、`optional`、`forbidden` 三组技能名，分别表示必须选择、允许选择和不应选择；不钉死唯一调用顺序。
- `expected.changed_files`：预期发生实质变化的工作区文件路径；空数组表示应零改动，其余文件保持不变。
- `expected.criteria`：需要裁判逐条核验的行为断言，包括决策、内容、适用边界和用户回报；不用固定措辞或完整标准答案代替行为要求。

追加失败题目时，保留能复现问题的最少原始信息，预期依据用户意图与真实契约确定。优先覆盖一个缺失的决策边界，已有案例只换了 ID 或名字时不重复堆题。适当保留不同表述的同类场景和反例，防止只修原题；不能为了让修订通过而同步放宽预期。

正例默认使用自然任务目标、问题现象或追问，不加入“修一下技能”“请记住”“记在项目约定里”等维护指令或写入位置提示。必要上下文可以提供真实规则和执行证据，但不提前判定根因、推荐修复或说明已有规则是否充分；明确调用测试另行标识，不能用来证明隐式召回。

分别检验“是否主动查因并正确分流”和“写出的规则是否有稳定价值”。同一问题表述可配规则缺陷、执行遗漏、环境故障等不同事实；有缺陷才修所属技能，已有规则完整则补正当前结果。运行前确定哪些情况必须选择、允许选择或不应选择技能，不以是否写入替代触发判定，也不为了得分迫使每次纠正都调用元技能。

提炼效果按适用条件、稳定要求和必要边界判定，不按是否复述用户原话判定。新增 few-shot 使用不同于评测题的题材，并在报告中区分修改前运行与修改后验证；仅按用户明确要求的范围运行，不因补充示例而自动再跑。

不应写入不等于不应触发。例如用户要求记住一个已覆盖的约定，错题本可以被正确选中，执行结果应为零改动。

## 长对话案例的截取

先确定要测的失败环节：没有选择技能、没有读取规则，还是读取后未完成。将题面截在错误回答之前的续做点，只保留自然纠正、必要的前序操作和可核验文件；观察到的失败结果与事后诊断放在 origin 或裁判记录，不给受试者。历史材料有分歧时保留分歧，不为了缩短上下文改成唯一正确答案。

较长的业务证据放入小型 fixtures，去掉无关闲聊、重复日志和真实标识；不靠无关文字凑长度。题面中的“此前已读技能”只是历史材料，不能当作本次受试读取成功的证据；读取后续做题重点判执行是否完成，不强迫重复声明已选技能。

当前工具将 prompt/context 作为一次输入，因此这种重建仅验证给定历史材料后的继续处理，不验证真实多轮状态延续或上下文压缩。真实压缩对照应另行准备原始输入、压缩事件及前后上下文，并记录实际技能读取与工具轨迹；没有这些材料时标记未测，不把手写摘要叫作压缩复现。长对话新题也按运行边界建立首次基线，不能因上下文较长而仅入库不运行；无法满足真实压缩条件时，如实限定本次能测的范围。

## 准备工具

使用 [skill_evals.py](../scripts/skill_evals.py)。各子命令都不调用模型，也不注册自动化；具体参数以 `--help` 为准。

```bash
python3 scripts/skill_evals.py validate ../mistake-notebook/evals/cases.json evals/cases.json
python3 scripts/skill_evals.py prepare evals/cases.json CASE_ID --stage trigger --skill-dir ../mistake-notebook --skill-dir . --output /tmp/skill-eval-run
python3 scripts/skill_evals.py inspect /tmp/skill-eval-run
```

以上命令从 self-improve-skills 目录运行；每次使用新的临时输出目录。执行效果阶段改用 `--stage execution`。仅为新题首次运行或用户明确要求的回归派发受试子智能体；明确暂存的案例不派发。本节不要求普通技能任务调用工具。

`subject/` 是受试者可访问的输入，`assessment.json` 是仅供裁判读取的预期、初始状态与哈希。派发时只给 `subject/` 路径，禁止访问其外部目录、真实技能、原题库或裁判材料；题设若要求编辑 `workspace/` 内的案例文件，该文件属于可操作 fixture，不是受保护的原题库。评测结束后删除这次创建的临时目录。

## 两个阶段独立评测

### 简介路由

新建不继承历史的原生子智能体（`fork_turns="none"`），只提供用户请求、必要上下文和候选技能的当前 `name/description`。不提供正文、标准答案、来源标签、案例编号或既往结论，也不额外告知被测目标；原题中用户明确点名的技能保留原样。

让它把选择的技能及简短理由写入 `selection.json`，格式为 `{"selected": ["skill-name"], "reason": "简短理由"}`；可以选择多个或零个技能。按 required/forbidden 检查选择，optional 不因选或不选扣分。

这一阶段测的是“简介能否支持正确选择”，不能替代宿主真实自动加载链路。首批候选范围是两个元技能；只有取得实际宿主加载记录时，才能报告真实触发结果。报告须注明候选范围。

### 执行效果

另建不继承历史的子智能体，在新的 `subject/` 下读取技能快照并完成原题，实际编辑 `workspace/` 的 fixture，最终用户回复写入 `response.md`。只允许修改测试工作区和指定响应文件；技能快照只读，不操作真实外部系统。

提供实际任务需要的工具及既有授权，不额外给出预期动作。评测材料不足、依赖无法在隔离目录中满足时，记录未测或证据不足，不回到真实配置“补齐”环境。

## 判分与回报

由父智能体或另一个独立裁判读取私有预期、`inspect` 输出、真实文件 diff、最终回复及必要执行记录。不能接受受试者自报“通过”作为证据。

- 确定性检查：技能选择、实际改动路径、未改文件哈希、文件格式。路径变化符合预期只说明范围正确，不能证明内容正确。
- 语义检查：逐条评估 `criteria`，核对长期性、归属、泛化边界、是否保留例外，以及更新回报是否与实际改动一致。指出对应证据，不按特定句式匹配。
- 分别报告路由和执行的通过/失败/未测数量及失败案例；未跑、证据不足和判断不明不能计为通过，不用合并总分掩盖某阶段失败。
- 记录案例集与技能快照哈希、实际模型、候选范围和评测阶段，便于下次对比；新题首次运行后建立行为基线，明确暂存的案例标记未运行。

用户只要求评测时，报告发现的问题；修订仍按实际授权范围处理。默认在本轮回复中给一份简短结果，不留下多份旁路报告、受试输出或临时 fixture。用户日后说“把这题加入某技能回归集”时，追加、校验并完成新题首次运行；明确说“只加题、先别跑”时仅保存。说“跑某技能回归”时，按指定范围重跑已有题。
