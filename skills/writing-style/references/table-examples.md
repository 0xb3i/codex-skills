# 表格场景与范例

按下表选择与当前阅读任务对应的小节，展示已有评估结果与样本，不执行评估或重新判分。

表头、列表、加粗和背景色遵循[信息呈现细则](information-presentation.md)。共同约束见[主文件](../SKILL.md)，数值展示按[第 3 节](#3-小数位与差值)的精度规则。

| 当前阅读任务与材料 | 规则入口 |
|---|---|
| 用具体值解释字段、指标或规则 | 第 1 节字段 Example |
| 核对同一问题下两组回答的差异 | 第 1 节对照组与实验组 |
| 案例资料较多、两组回答较长，需要就近核对依据 | [完整案例对比表](case-comparison-layout.md) |
| 理解条件变化如何改变工具调用或返回结构 | 第 1 节结构化输出 |
| 比较已有模型评估数值 | 第 2 节训练结果；训练进度、配置和 loss 曲线按其本身组织 |
| 新增数值、计算差值或按要求统一精度 | 第 3 节小数位与差值 |
| 展示同批匹配样本的已有逐样本 GSB 判定分布 | 第 4 节 GSB |

**评测结果解释**

案例说明该样本的可观察差异；总体效果使用对应样本范围的汇总结果。

## 1. 带 Example 的表格

**展示规则**

- 字段说明表一行解释一个字段，Example 给具体值。示例取自素材，或在用户要求教学示例时明确标为示意。
- 同一问题的两组回答放在相邻列，问题只写一次，对象顺序保持一致；按当前材料使用“对照组／实验组”或实际名称。仅在核对结论需要时增加来源证据或差异说明列，不固定附加翻译、产品描述等业务列。两份较长内容需要保留各自完整结构时，再考虑[双栏对照](information-presentation.md#3-双栏对照)。
- Bad Case、strict 扣分或 Gold 正确性分析使用 `Query`、`Gold`、`SFT`、`Remark` 四列；训练前后行为对比使用 `Query`、`Base`、`SFT`、`Remark`。一行一个样本，Query 保留完整用户问题，不能把 Base 当成 Gold。
- 非 SFT 模型沿用材料中的实际名称。
- 工具调用样本中，模型与 Gold 单元格只放与判断有关的调用 JSON，多次调用按执行顺序排列；富文本单元格内使用 JSON 代码块。文本回答任务保留相关回答，不强制转成 JSON。
- 工具调用计划与工具返回结果按素材明确标注，不把模型计划写成已执行成功的返回。结构化内容保留字段层级、数据类型及必要上下文，不能仅用“换了工具”代替实际差异。
- 只高亮与当前判断有关的短语、字段、值或差异行，共同内容保持普通样式。代码块使用原生片段／行高亮；不往 JSON 中插入 Markdown 加粗符号、注释或“[高亮]”标记。平台不支持代码内高亮时，在相邻说明中明确指出并强调字段差异，保留可复制的合法 JSON；普通语法着色不等于差异高亮。
- Remark 说明真实需求、输出差异和有证据的判断。模型错误、合理多解、Gold 或评估器问题须有当前材料依据；信息不足时保留待确认，不通过润色重新归因。

**具体例子**

字段说明表的示意：

| 字段 | 含义 | Example |
|---|---|---|
| `query` | 用户希望查找的商品 | `防水登山鞋` |
| `max_price` | 价格上限，单位为美元 | `50` |

工具调用错误样本的示意：

| Query | Gold | SFT | Remark |
|---|---|---|---|
| 帮我找不超过 50 美元的防水登山鞋。 | `{"tool":"search_products","args":{"query":"防水登山鞋","max_price":50}}` | `{"tool":"search_products","args":{"query":"防水登山鞋"}}` | 用户要求价格不超过 50 美元。此示意假设工具不会从 query 外补充价格条件，SFT 遗漏了价格上限参数。 |

上表用行内 JSON 展示 Markdown 预览；写入飞书时，将相应单元格中的调用放进原生 JSON 代码块。

明确分析训练前后行为时，改用以下示意结构：

| Query | Base | SFT | Remark |
|---|---|---|---|
| 帮我找不超过 50 美元的防水登山鞋。 | `{"query":"防水登山鞋"}` | `{"query":"防水登山鞋","max_price":50}` | 此样本中，SFT 增加了用户要求的价格上限。 |

具体值帮助读者理解字段，样本对比帮助读者核对判断依据。反例是在进度表中强加 Gold、SFT 列，或只写“参数有误”而不展示用户要求和相关输出。

### 对照组与实验组

先按信息量选择布局：共同资料较多、两组回答较长时，优先采用用户认可的[完整案例对比表](case-comparison-layout.md)，在同一张两列表内先放资料、再并排放完整回答。下方三列范例适合简短回答或明确要求展示节选的场景；不能用它替换支撑正文论据所需的完整案例。

以下是构造的背包问答示例。同一问题的两组回答按列并排；表内保留各一条相关理由，加粗模拟需要局部高亮的片段。实际文档可按已有样式给两侧差异使用浅橙、浅绿背景；颜色用于定位差异，不能据此宣称总体收益。

| 问题 | 对照组回答节选 | 实验组回答节选 |
|---|---|---|
| Is this backpack suitable for a day hike? | Its **lightweight** design makes it easy to carry. | Its **ripstop nylon and adjustable chest strap** support durability and a more stable fit. |

该构造例的阅读重点是回答引用了哪些商品信息。标题为“Lightweight Daypack”，描述为“Made of ripstop nylon with an adjustable chest strap”；对照组引用标题中的性质，实验组引用描述中的材质与结构，资料区并列提供标题、描述及翻译供核对。需要判断这些理由是否有依据时保留相关证据；只演示对照形式时可像上表一样明确标为节选。不能把单个案例中的变化外推为总体效果。

### 表格内的结构化输出

同一 Query 下比较工具计划时，可以按“场景／工具调用计划”分行，代码块获得更宽的阅读空间。若多条 Query 都要比较两组输出，沿用相邻的对照组、实验组列，每个单元格放对应代码块；由实际阅读任务选择方向，不强制所有 JSON 都横向并排。

构造示例的 Query：

> I'm planning a day hike—what backpacks are popular right now?

此例高亮两处工具名及 `ranking_metric`，使读者直接看到语义搜索与榜单调用的区别。它展示的是模型生成的工具调用计划，未展示工具实际返回。展示真实返回 JSON 时，将列名改为“工具返回结果”，按同样原则标出相关字段或值。

**采用理由与反例**

相邻列让读者在同一行完成回答对比，单元格代码块保留结构，局部高亮缩短查找差异的时间。

- 反例：两组回答分散在相距很远的段落，读者需要记住前一段才能比较；或整列铺色、全文加粗，关键差异仍需自行寻找。
- 正例：同一问题占一行，两组回答相邻，只强调与当前结论有关的片段。
- 反例：把 `"tool":"**query_catalog_ranking**"` 写入 JSON，改变工具名；只用自然语言写“使用榜单”，省略判断所需的参数。
- 正例：代码块保留原始 JSON，通过原生样式高亮工具名和关键参数；不支持局部高亮时，在相邻说明中写明“工具改为 `query_catalog_ranking`，并增加 **`ranking_metric` 取值 `weekly_sales`**”。


## 2. 训练结果表

**展示规则**

- 主结果表首列放评估维度，按已有材料展开总体及业务域；后续按模型分组，每组使用相同指标顺序。只有一个模型时保留一组，不为凑表增加模型。
- 基线明确、只需同时查看候选结果及其变化时，默认把差值附在候选值后，写成“结果值（带符号的变化）”，不再单列重复差值。百分率的绝对差写 `pp`（百分点），相对变化才写 `%`；沿用已有数值和精度，不能为套格式重算。
- 需要独立比较多组训练收益，或同时展示绝对与相对变化、使单元格过长时，可保留独立对比列。此时列名写 `Base vs SFT`，不写 `Base → SFT`；表下注明差值方向为 SFT 减 Base。对比值写“绝对变化（相对变化）”，正向示意为 `+0.1259（+16.19%）`，精度按第 3 节处理。
- 总体与分域尽量合并进同一张主表，不重复建方向相反的总表。仅总体有值的指标，分域写“—”，必要时表下注明缺失原因；不能填 0 或拿总体值充当分域值。
- 维度名称不附加 `n=`；必要的样本量放在表下注释。只展示已有的 strict、adjudicated、Schema valid、Sample exact 等结果，不补造列值。
- 模型名称沿用素材，不添加未经确认的架构、训练类型前缀或别名。

**具体例子**

以下构造 200 个样本的两组分类评测数据，说明单一基线与候选的准确率对比，差值就近放在候选列中：

| 维度 | 样本数 | 模型 A | 模型 B |
|---|---|---|---|
| 文本分类 | 120 | 65.0% | **85.0%（+20.0 pp）** |
| 意图分类 | 80 | 75.0% | **90.0%（+15.0 pp）** |

括号表示候选减基线的百分点差，结果和变化在同一格内即可读完；关键结果的强调遵循信息呈现规则，不自动整列铺色。反例是在候选值后已有变化时仍增设“差值”列，或把 `+20.0 pp` 写成 `+20.0%` 而混淆绝对差与相对增幅。只有单模型结果、比较基线不明确或差值无来源时，不补括号变化。此范式是[视觉强调示例](information-presentation.md#4-视觉强调)中“结果值后附变化”在表格内的应用。

同一评分指标下，两组模型训练结果的示意。富文本表格可用两层表头，上层按模型合并，下层保留 Base、SFT、Base vs SFT；Markdown 预览如下：

| 评估维度 | 模型 A Base | 模型 A SFT | 模型 A Base vs SFT | 模型 B Base | 模型 B SFT | 模型 B Base vs SFT |
|---|---|---|---|---|---|---|
| 总体 | 0.8000 | 0.9000 | +0.1000（+12.50%） | 0.8200 | 0.9020 | +0.0820（+10.00%） |
| 选品域 | 0.7500 | 0.8500 | +0.1000（+13.33%） | 0.7800 | 0.8580 | +0.0780（+10.00%） |
| 创作域 | 0.8500 | 0.9500 | +0.1000（+11.76%） | 0.8600 | 0.9460 | +0.0860（+10.00%） |

此示意差值为 SFT 减 Base，相对变化以 Base 为分母；总体示意采用两个域等权平均。真实表格保留原有聚合口径，不能擅自平均分域得分生成总体值。

需要进一步展示分指标结果时，将不同业务域的专属指标分别放入对应小节：选品域可含已有的 Filter、Board、选品 Query，创作域可含 Param Match、Product Selector、Video Length、创作 Query；公共指标可在各域展示。各域专属指标保留其适用范围。

选品域分指标表的示意：

| 指标 | 模型 A Base | 模型 A SFT | 模型 A Base vs SFT |
|---|---|---|---|
| Filter | 0.8000 | 0.8800 | +0.0800（+10.00%） |
| Board | 0.7000 | 0.8400 | +0.1400（+20.00%） |

**采用理由与反例**

相同模型列组让读者直接比较同一指标，分域表保留指标的适用范围。反例是把总体聚合值复制到各域，或在只有 Base 结果时编出 SFT 列值。

结果说明可按“整体 → GSB／人工评估 → 分维度 → Bad Case → 校正结果”展开，仅保留当前材料实际包含且获准修改的部分。表前在必要时说明读表目的，表后解释关键发现，不逐格复述；案例靠近对应结论。只说明训练过程正常的 loss 曲线可下沉，影响模型选择的异常保留在正文。

## 3. 小数位与差值

**展示规则与例子**

下表只用于新生成数值且没有既定精度的情况；不据此批量舍入已有源值。

| 数据类型 | 默认展示 | 示例 |
|---|---|---|
| 模型评分及其绝对差值 | 四位小数 | 0.8000、0.9000、+0.1000 |
| 新计算的比例或相对变化 | 百分号前保留两位小数 | 60.00%、+12.50% |
| 两个百分率的绝对差值 | 两位小数，单位为百分点 | 80.00% 到 90.00%，绝对变化为 +10.00 个百分点 |
| 样本数、次数 | 整数 | 100，不写 100.00 |
| loss、耗时、金额等其他数值 | 沿用指标单位和既定精度 | 原文 1.5s 保留 1.5s，不套用评分四位小数 |

- 同一指标的同组新生成数值保持精度一致。默认精度若会将有意义的差异舍入为 0，或掩盖判定阈值，提高该组展示精度；不能为了整齐改写已有源值。
- 差值使用未舍入的原始数据计算，最后才格式化。只在任务需要且来源充分时计算，不用重算值覆盖既有差值；发现矛盾时指出并保留原文。
- 对正基准评分，绝对变化为候选值减基准值，相对变化为绝对变化除以基准值。示意：0.8000 到 0.9000 写 `+0.1000（+12.50%）`。负基准或特殊指标沿用其既定口径，不自动套公式。
- 基准为 0 时保留可计算的绝对变化，相对变化写 `n/a`。示意：0.0000 到 0.1000 写 `+0.1000（n/a）`。缺少结果写“—”，不能用 0 代替；`n/a` 与缺失结果含义不同。
- 百分率变化区分百分点与相对百分比。80.00% 到 90.00% 的变化为 `+10.00 个百分点（+12.50%）`。

**采用理由与反例**

单位和精度帮助读者区分评分差、比例与百分率差，也防止舍入改变判断。反例是把 80.00% 到 90.00% 写成“相对提升 10%”，或只因模板规定四位小数，就把源值 0.812345 改成 0.8123。

## 4. GSB 表格

沿用项目已有 GSB 定义，展示同批匹配样本的改善、持平和退化分布。平均得分、训练 loss 或单模型正确率无法反推出逐样本 GSB 判定。

**展示规则**

- 比较方向在紧邻表格的正文中交代，例如“候选 SFT 相对基线 Base”，不单设“对比方向”列；上下文已清楚时不重复说明。Good 表示候选更好，Same 表示按既定规则持平，Bad 表示候选更差；不在不同表格里反转方向。
- 二元正确性口径中，基线错而候选对为 Good，正确性相同为 Same，基线对而候选错为 Bad。连续得分或人工偏好评估沿用已有阈值和判定，不自行设置容差；缺少口径时说明缺失，不能补判。
- 汇总表默认使用“样本数／Good／Same／Bad”四列，表头不追加“数量（占比）”，单元格直接写“数量（占比）”，如 `27（13.50%）`。只有多行确需区分业务域、数据集等范围时，才增加相应标识列；单行总体结果不强加“比较范围”列。占比使用同一行有效匹配样本数作分母，包含 Same；排除、未匹配、未判定样本不悄悄计入有效样本数。
- G、S、B 应互斥且覆盖该行有效样本；检查数量相加等于有效样本数，占比按未舍入计数计算。舍入后总和可能不恰为 100.00%，不要手改某个比例凑整。
- 项目需要展示 `Good - Bad` 时，明确单位为样本数。若采用 `(G-B)/N` 等比例，写出公式与分母并沿用项目定义；不统一命名为含义不明的“GSB 分数”。
- 不从净值直接宣称统计显著或整体稳定性；保留 Bad 的数量，让读者看见退化。案例判断来自已有评估，不能拿历史案例当本次结果。

**具体例子**

以下为 SFT 相对 Base 的示意，采用已有的逐样本质量判定：

| 样本数 | Good | Same | Bad |
|---|---|---|---|
| 100 | 60（60.00%） | 25（25.00%） | 15（15.00%） |

分母为 100 个已匹配且完成判定的样本，包含 Same。表后确需说明时可写：“候选在 60 个样本上改善、15 个样本上退化，另有 25 个持平。”只有任务需要净值时才加 `Good - Bad（样本数）` 列，本例为 `+45`；需要分域时添加业务域标识及有对应数据的行。

需要解释 GSB 的具体样本时，使用下表；本示意假设已有逐样本正确性结论：

| Query | Base | SFT | 判定 | Remark |
|---|---|---|---|---|
| 17 加 25 等于多少？ | 41 | 42 | Good | 基线回答错误，候选回答正确。 |
| 6 乘 7 等于多少？ | 42 | 42 | Same | 两者均正确，按本例正确性口径持平。 |
| 9 乘 8 等于多少？ | 72 | 63 | Bad | 基线回答正确，候选回答错误。 |

真实任务沿用完整 Query 和相关实际输出；工具调用场景按第 1 节使用 JSON 代码块，Remark 解释判定依据。此三行用于分别说明类别，不是上方 100 个样本的明细，也不能用来推算该汇总表。

**采用理由与反例**

明确方向和分母后，读者才能理解候选改善了多少、退化了多少。反例是只写“GSB 为 45%”而不说明公式，或用两组平均分直接编出 Good、Same、Bad 的数量。
