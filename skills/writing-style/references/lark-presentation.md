## 1. 标题与列表编号

飞书章节需要“2.”“2.1”这类层级编号时，使用原生自动编号，标题文字只保留主题，不手写数字前缀。已有手写章节编号在获准修改时迁移为自动编号，保持原有层级和顺序；不据此给未编号标题强加序号，也不删除“Case 1”或版本号等有实际含义的标识。写入后核验自动编号设置与标题正文，避免双重编号。

怀疑列表编号错误或需要核验编号修改时，读取[有序列表编号核验](numbering-verification.md)，按页面和原生列表状态核实后再修改。

## 2. 表头与分类样式

目标格式支持背景色时，表头默认使用飞书内置的中蓝色背景，表头文字保持清晰可读；用户已经设置具体颜色时，沿用其选择。本次用户选择的中蓝色色值为 `rgb(225,234,255)`（`#E1EAFF`），不要替换成更浅的 `rgb(240,244,255)`。不要默认采用浅灰表头，也不要把表头底色扩展到整张表。这里约定的是表格 header，不据此将所有章节标题统一改成蓝色。

分类表数据区保持无背景色，用合并单元格和表格边界区分类别，不再给各组铺不同底色；蓝色表头继续保留。必要的关键结果强调仍遵循“视觉强调”，双栏布局的背景约定不受影响。

**示例**

- 表头反例：新建指标表时仍使用浅灰色表头，忽略文档中用户已设置的蓝色样式。
- 表头正例：“环节／主要指标／观察重点”三列表头均使用飞书内置中蓝色背景，数据区保持普通底色；保存后核验实际背景样式。
- 分类表正例：保留中蓝表头，数据区不铺色；分类由合并单元格表达，关键结果按视觉强调局部处理。

## 3. 双栏与视觉强调

双栏应有清楚的背景分区：每栏使用独立的浅色背景包裹本栏内容，默认两侧使用不同颜色，例如左侧浅蓝、右侧浅绿，并保留栏间留白和适当内边距，让读者一眼看清各段属于哪一侧。避免使用浅灰背景造成整体观感灰暗，也不要只把文字左右摆放在同一白底上，或用一整块连续底色覆盖两栏。配色保持浅淡，保证文字清晰；用户已有明确配色时沿用其选择。这里的底色用于区分对象，不表示优劣，局部指标着色仍遵循“视觉强调”。

背景色必须实际写入并保存到文档组件。核验时读取保存后的样式，或在光标移开、取消选中后检查显示效果；不要将 hover、focus 或选中态产生的临时底色当作已设置的背景。

正文加粗可以保持默认黑色，也可以配合蓝色文字突出重点；按内容灵活使用，优先沿用用户已设置的强调方式。不把全部加粗统一改蓝，也不规定某一类文字必须固定用黑色或蓝色。蓝色文字用于阅读强调，不自动表示指标改善；表头背景色遵循“结构化表格”的约定。

有依据的明显正向改善，可以使用浅绿色背景并加粗关键结果或变化幅度。强调对象与改善方向按[视觉强调](information-presentation.md#4-视觉强调)判断。

飞书双栏使用原生分栏组件，具体语法按“原生组件与公式”读取当前工具说明。

**示例**

- 背景反例：“节点评测”和“端到端评测”仅靠左右摆放区分，文字与页面同为白底；或两侧统一使用浅灰底，缺少颜色区分且页面观感灰暗。
- 背景正例：“节点评测”使用浅蓝背景，“端到端评测”使用浅绿背景，各自包住标题、要点和资料链接，中间保留白色间隔。
- 文字颜色反例：看到一处蓝色加粗，就把全文所有黑色加粗一并改蓝。
- 文字颜色正例：沿用用户对“使用 → 选品 → 发文 → 动销”设置的蓝色加粗（示例色值 `rgb(36,91,219)`），其他位置根据内容保留黑色加粗。

## 4. 原生引用

引用飞书文档时，直接粘贴原始文档 URL，让平台识别为原生文档引用。禁止写成 `[文档名称](URL)`、HTML `<a>` 或其他自定义文字超链接，也不要把原始 URL 包在代码格式中。此规则适用于正文、列表、表格单元格和引用块中的 Docx、Wiki 等飞书文档引用。

通过工具编辑飞书时，使用与粘贴原始链接等效的原生文档引用组件，并保留已有原生引用；回读验证引用类型和目标文档，不能只检查文字能否点击。涉及原始链接中的定位锚点或参数时保留其定位含义，无法保留时直接贴完整原始 URL，不擅自裁剪。

行内引用与前后文字之间各留一个空格。空格放在引用外部，不修改 URL，不重复插入多个空格；位于段首或段尾、没有相邻文字的一侧无需补空格。

引文和短注释使用原生引用块，内容、标签与位置按[引用块](information-presentation.md#5-引用块)处理。

自定义文字超链接可能无法被飞书识别为文档引用，导致“本文引用”不显示对应文档。原始链接经平台识别后形成的原生引用能保留文档关联。

**示例**

- 飞书引用反例（构造）：`参照 [示例项目体验文档](https://example.com/docx/EXAMPLE_DOCUMENT) 完成产品体验。`
- 飞书引用正例：直接粘贴当前任务提供的完整 Docx/Wiki URL，由飞书生成原生文档引用；通过工具编辑时直接写入对应原生引用组件。
- 留白反例：`参照〈原生文档引用〉完成产品体验。`
- 留白正例：`参照 〈原生文档引用〉 完成产品体验。`

以上代码格式与“〈原生文档引用〉”仅用于展示规则，实际正文不保留代码格式或占位文字。

## 5. Callout 样式

Callout 使用浅色背景和同色系、略深且可辨识的边框，保证文字清晰；平台支持时同时设置并核验背景色与边框色。同类用途沿用一致样式，不同用途按需要区分，图标与内容相符。配色沿用用户已确认的选择及当前适用的界面规范。

**示例**

- 样式反例：所有 Callout 都固定用浅蓝色加 💡；或为了保证图标不重复，给测试说明选择无关的庆祝图标。
- 样式正例：本篇中，入门信息可用浅蓝底与蓝色边框配 📖，示例可用浅橙底与橙色边框配 💡，测试说明可用浅绿底与绿色边框配 🧪。

## 6. 原生组件与公式

实际编辑飞书时，联动 `lark-doc` 技能及其 CLI 参考，按所用组件读取相应操作说明；涉及画板等资源时按文档技能路由处理。组件语法和能力以当前工具文档为准，本技能维护选用原则，不重复保存整套 CLI 命令。写入后核验结构和样式；图示需检查实际呈现。平台不支持目标形式时，采用能保留信息关系的可用形式，不声称已实现不存在的样式。

展示比例、分式等数学关系且普通文本难以阅读时，优先使用原生公式；inline code 用于代码和标识，不用来包裹整段中文计算口径。公式用清楚的短名称，完整限定条件紧邻公式保留，原属表格的公式与口径仍在同一单元格。列表和单元格内的公式默认使用紧凑行内样式，字号与相邻正文协调；不要默认使用展示型大分式（如 `\displaystyle`），导致公式突兀或明显撑高行距。例：回购率用“回购去重用户数／购买去重用户数 × 100%”的原生分式，同条说明统计周期及“购买过该商品至少一次”的口径，避免把整句长中文塞进分子、分母。简单加减关系或普通定义用自然文字即可；写入后检查分式、换行和单元格边界的实际呈现。

**示例**

- 反例：在飞书正文中写“[绿色高亮] 0.8400”，用空格模拟表格对齐，或把“Callout”当作普通段落标题后声称已经完成高亮。
- 正例：创建原生评分表，在关键结果处实际设置浅绿色背景和加粗，将结果摘要放进原生 Callout，并核验写入后的内容与格式。

## 7. 素材复制

优先通过目标平台支持的原生资源复制方式保留图片质量和画板的可编辑性，不修改来源文档。素材选择、口径与图源标注按[素材复用](information-presentation.md#7-素材复用)处理。

原生画板复制失败时，如实报告失败，在交付回复中提供源画板链接和插入位置，交由用户手动复制；未经用户明确要求，不得用截图、导出图或重绘图替代原生画板，也不得声称复制已完成。这不影响直接复用参考资料中原本就是图片的素材。

**示例**

- 失败处理反例：原生画板复制失败后，擅自插入高清导出图，并将素材复用任务标记为完成。
- 失败处理正例：说明原生画板复制失败，提供源画板直达链接和主文档中的插入位置，留给用户手动复制。

## 8. 画板创建与核验

在已获准创作、结构优化或调整相应章节的飞书文档中，选用图示后主动生成并插入原生画板。已有适用图示先按[素材复用](information-presentation.md#7-素材复用)处理；更新现有画板时复用其 token。只要求聊天中给文案时，不创建或写回飞书文档。

图示内容、布局及插入位置按[架构与流程图示](information-presentation.md#10-架构与流程画板)组织。

- **生成与插入：** 先读取 `lark-doc` 的画板处理指南，由其负责文档位置与画板创建；复杂图的创作及已有画板编辑调用 `lark-whiteboard`，按当前 CLI 工作流执行，所需子智能体协作也遵循该流程。简单图可由文档 CLI 直接生成原生画板。不在本技能复制命令、格式或固定图形语法，不停留在“建议加图”、源码或空白占位画板。
- **完成核验：** 回读文档，核对画板位置和实际内容，并检查画板 CLI 导出的实际预览；不能以“已下载”“文字可读、线已连上”代替视觉检查。逐项检查标签是否位于对应节点或连线上、有无多余说明、连线是否绕行或相交，以及整体对齐、间距、留白、配色层次和图文一致性；按文档展示尺寸检查可读性。有问题就在当前画板修正并重新核验。仅创建 token、生成本地代码或插入空白画板不算完成。已有原生画板复制失败时，按[素材复制](#7-素材复制)处理，不借此擅自重绘替代。

原生画板便于继续编辑，完成插入与预览核验才能确认读者实际看到的是可读的图示。
