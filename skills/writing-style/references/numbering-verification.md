# 有序列表编号核验

## 适用条件

审阅已有文档时发现疑似重复、重启或跳号，或实际修改了有序列表、需要核验编号时使用。只读内容摘要、普通段落润色、没有编号疑点的任务不需要额外查询。这里负责判断证据是否足以提出修改；平台编辑仍交由对应文档技能。

## 已验证的读取差异

2026-09-13，使用 lark-cli 1.0.94 读取同一份飞书文档的“编译与发版”和“模型部署”，XML 与 Markdown 都把被图片、代码块或说明段落分隔的列表项显示为 `1.`。原生 Block API 中，各节首项的 `ordered.style.sequence` 为 `"1"`，后续项均为 `"auto"`，且处于相同父节点。用户已确认页面正常连续编号。

这证明导出标记不能直接代表页面显示，不能据此说作者把每一步都写成了 1；当前证据也不足以断言缺陷发生在 CLI 本地还是服务端转换。换成 Markdown、重新拉取全文或增加 `--detail full`，都不能视为独立的页面核验。

## 核验流程

1. 读取疑点所在的完整步骤范围，保留 block ID、层级、前后列表项及穿插的图片、代码块和说明。不根据孤立片段或 `<ol>` 被拆开就判断列表重新开始。
2. 飞书文档先检查原生列表属性。通过 `lark-cli docs --help` 确认是否已有原生 Block 读取命令；没有时，可使用下方已验证的只读 API。核对 `block_type`、`parent_id`、`ordered.style.sequence` 和内容，不能只看导出的 `seq-marker`。
3. 原生 `sequence="auto"` 表示自动编号，不等于数字 1，也不单独证明页面应显示哪个数字。首项为 1、后续为 auto 时，不报告“所有步骤都是 1”。若需确定具体显示值，再结合实际页面呈现及相同列表的上下文核验；只凭同父节点或条目数量不能重算整篇序号。
4. 多项显式设置为 1 也可能是有意开启不同列表。只有可靠的页面证据与步骤关系共同证实不合理的重启或跳号时，才标注具体位置。原始数据不可读、页面无法核实时，将编号问题视为证据不足，不新增 review、不修改文档，也不机械地要求用户确认每个序号。
5. 用户已确认页面编号正常时，保留原样，不重复报同一问题。禁止为了让导出文本看起来连续而把原生自动编号改成硬编码数字，或移动、重建原有列表。

## 飞书原始编号读取

将 `DOCUMENT_ID` 和 `BLOCK_ID` 替换为本次读取所得的真实标识，不复用示例文档的固定 ID。下面只读取属性，不写文档：

```bash
lark-cli api GET '/open-apis/docx/v1/documents/DOCUMENT_ID/blocks/BLOCK_ID' \
  --as user \
  --jq '.data.block | {block_id,block_type,parent_id,sequence:.ordered.style.sequence}'
```

本轮验证中，`block_type=13` 对应有序列表。没有 `ordered` 字段时，先核实真实块类型，不把字段缺失解释成“没有编号”。访问失败按原权限或网络错误处理，不降级猜测文档有误。

## 正反例

| 读取证据 | 正确处理 | 错误处理 |
|---|---|---|
| 图片之间导出为 `1、1、1、1`；原始属性为 `1、auto、auto、auto` | 识别为有序列表及自动编号，不据导出值报错 | 评论“请补充 1、2、3、4”，或直接重编号 |
| 只截取到某个自动编号项，片段显示为 `1.` | 扩展必要上下文；无法确定页面数值时不作编号结论 | 认定该条在原文中从 1 重启 |
| 两个独立小节的首项均显式为 1 | 保留各自列表起点 | 按整篇出现顺序强制连续编号 |
| 页面确实把同一流程显示成 `1、2、1、2`，原始属性和步骤关系也证实中途错误重启 | 只指出实际重启位置，按获准范围修改后核验页面 | 因曾遇到导出误报，就一律忽略真实编号问题 |

## 完成标准

提出编号 review 时，必须能说明具体的页面问题及其核验依据。只拿到转换后的序号、自动编号属性或不完整片段时，不构成可提交的编号问题。此规则修正审阅判断，不声称已经修复上游导出器。
