# 周报与进展条目

## 适用范围

用户需要撰写、改写或压缩周报，或向老板、leader 同步同类项目进展时使用。默认读者需要快速了解这周做了什么、解决了什么业务问题、前后有什么变化、目前到哪一步。用户明确指定其他受众或格式时，以其要求为准。

本分支只负责文案。周报必须仅在聊天中提供可粘贴的文字描述，由用户自行填入飞书；禁止直接创建、修改或写回飞书周报，也不发送周报消息。用户提供周报链接仅授权读取和参考，不构成写入授权。不因素材包含服务、模型或发布状态就检索日志、执行训练、发版或修改项目状态。技术评审、故障复盘、详细实验报告、操作交接不套用周报的精简格式；混合文档只在承担进展同步的部分使用本分支。

## 个人研发周报取材与延续

**适用条件**

为用户撰写个人研发周报、补齐本周进展或根据 MR 整理工作时执行。先从当前任务或项目约定确定作者、相关仓库与周报位置；仅润色用户已经给定的完整条目、调整格式或撰写其他业务周报时，不自动扩查仓库和文档。

**规则与来源**

- 按用户或项目约定的时区确定周期起止日期：用户指定范围优先，其次采用周报中当前待填写周期；未指定且文档无法确定时，按已确认的惯用周期选择最近一个已结束的周期，尚无周期约定时先核实。先固定时间窗口，不直接用滚动七天或自然周代替。
- 通过当前代码平台的只读能力核实作者身份，读取该窗口内本人创建的 MR；按任务与项目约定覆盖所有相关仓库。覆盖打开、已合入和关闭状态，检查分页；以创建、更新或合入时间检索候选，再核实本周实际增量，排除只有无关状态更新的旧工作。跨周 MR 保留本周的变化，不重复算作新开发；时间窗口外的改动不混入本周。
- 阅读相关 MR 的描述与必要 diff，明确解决的问题、行为变化及当前状态；不能只按标题猜测两个 fix 的作用。正文按项目合并两端改动，不写 MR 流水账；MR 链接、时间和证据留作核对，是否进入正文按读者需要决定。
- 通过对应文档技能读取用户或项目指定的周报中上一个周期的本人相关条目，并查看本周已有内容。按项目接续上周的进度、待办和依赖，突出本周从开发到上线、从灰度到扩量等实际变化；沿用已有项目名称和归属，保留其他人的内容及用户已定稿文字。
- 用户当轮给出的上线、实验比例、开发完成及后续计划是当前状态素材；与 MR、旧周报分别核对，按“结果与状态”记录阶段、范围和条件。
- 工具或看板用途需要强调时，将开发成果与具体用途连接，例如定期收集并留存线上 badcase，为后续模型重训和回归评估积累样本。
- 来源读取失败时，完成已有素材支持的部分，并向用户指出实质缺失；不编造 MR 或继承未经核实的历史状态。取材和周报链接均仅用于只读参考，成稿按本分支边界在聊天中交付。

**采用理由与正反例**

MR 补齐本周具体改动，上周周报提供项目状态基线，用户补充当前交付与实验进度；结合三者才能写清本周增量和后续条件，避免漏项或每周重讲同一成果。

- 反例：只查前端仓库；将上周“导出工具开发中”照搬到本周，或把打开的接口修复 MR 写成“已上线”。
- 正例：在构造的前后端项目中同时核对两端导出功能的改动，接续上周开发状态写本周上线；接口修复说明具体问题，并按 MR 实际状态写“已提交 MR，待合入”。

## 内容取舍

从素材识别项目、问题、原方案不足、本周动作、结果、状态和依赖。同一主题合并重复信息，突出本周增量；过程流水和实现细节只有影响结果、风险或决策时才保留。公共表达与共同约束沿用[主文件](../SKILL.md)。

| 读者的问题 | 条目中保留什么 | 避免什么及其问题 |
|---|---|---|
| 为什么要做 | 当前问题，以及理解改动所需的原方案不足 | 重讲读者已熟悉的完整背景，掩盖本周变化 |
| 这周做了什么 | 已完成或正在推进的关键动作；技术用一句短语点明，如 SFT 训练、服务端联调、接入榜单工具 | 罗列脚本、参数、路径、接口字段或会议流水，让读者自行归纳成果 |
| 做完带来什么变化 | 有依据的前后能力变化或业务结果；将技术动作连接到具体用户任务 | 只有“完成开发”而没有用途，或把预期收益写成已实现收益 |
| 现在到哪一步 | 开发、联调、测试、部署的实际状态与环境；有实质影响的阻塞或依赖 | 用“已完成”“已上线”笼统代替各环节状态，导致读者误判可用范围 |

这四个问题用于取舍材料，不是要求每条固定写四句、四个标签或统一以“为了解决……”开头。问题与原方案不足可合成一个短句；背景已知且本周只更新状态时直接写增量。不为凑模板添加“指标待补充”“负责人待确认”等占位。

技术细节以足够解释做法为限。SFT、MCP 等名称可在受众熟悉时直接使用；陌生且影响理解时按通用术语规则简短解释。默认省略合入分支、MR 编号、字段枚举、兼容与异常处理清单，除非这些细节本身影响读者的判断或是用户要求核对的对象。工具名、版本、时间、指标和依赖只有用于辨认交付对象或影响判断时保留，不能因追求短而删掉关键限定。

**采用理由**

leader 需要据此判断项目价值、进度和是否需要介入。明确问题、动作与前后变化能说明工作的意义，具体状态能说明成果目前在哪里可用；实现过程通常不参与这些判断。

## 条目格式

沿用用户已经确认的格式。未指定时，每个项目使用一个 bullet point，以加粗的简短主题加冒号开头，例如 `- **模型训练：**`、`- **MCP 开发：**`，后接简洁、连贯的说明。这里是正文要点标签，可以使用冒号；不受章节标题禁用冒号的限制。

一条优先围绕一项主要进展，用少量短句讲清楚，通常以当前状态收尾。状态或阻塞本身是本周重点时可以前置，不固定句数或字数，不把有意义的多个变化硬压成含混的一句。

同一项目有多个需要独立判断的事项时再拆条或分组；默认不将每条都展开成“背景／技术方案／结果／下一步”多级列表。不为短条目额外增加摘要、表格或架构画板；确需比较多组数值或解释复杂关系时，再按对应呈现规则处理。

## 结果与状态

- **前后变化：** 有真实结果时写清基线与当前值，并保留影响判断的统计口径、样本范围和不确定性。旧周报指标只有本周出现新增证据时，才作为本周新增结果。派生变化仅在任务需要且数据足够时按[小数位与差值](table-examples.md#3-小数位与差值)计算。
- **能力与收益：** 按材料区分开发成果、已实现能力、已验证业务结果和预期用途；离线评分与线上收益各用对应证据。例如固定榜单接入可支持按榜单查询商品；badcase 看板可为后续重训积累样本，重训完成与效果提升另需对应结果。
- **交付阶段与环境：** 开发、MR、测试、部署、接入和验收分别记录实际阶段及待完成依赖。例如“已提交 MR，待合入”“MR 已合入”“开发完成，待测试”“测试通过，待上线”“已部署 UAT，待验收”“已上线生产”。环境与验收结论使用材料已提供的信息。
- **多个交付侧：** 工具开发或上线、Agent 接入、模型部署及实际承接流量分别记录，写清每侧已达到的阶段及依赖。
- **实验流量：** 实验放量比例与实验组推全量分别说明，保留后续条件。例如“AB 实验已由 50% 放量至 100%，本周观察无问题后将实验组推全量”。
- **阻塞与下一步：** 阻塞影响交付或需要 leader 协调时，在相关条目中写清已知依赖。仅在用户要求或素材明确提供下周计划时单列下一步，沿用其栏目名称；不自动加计划、负责人、日期或新的实验任务。

## 完整示例

以下为构造素材与成稿示例。

**模型训练素材**

此前主要靠 Prompt 约束工具调用，复杂条件容易遗漏；本周完成针对这些条件的首轮 SFT；尚未完成离线评估，未上线。

- 反例：完成数据脚本调整、训练参数配置、任务提交和 checkpoint 导出，通过 SFT 显著提升了规划准确率，项目已完成。
- 问题：堆积实现过程，编造已验证效果，并用“已完成”掩盖评估和上线状态。

**MCP 开发素材**

原方案只能语义搜索护肤商品，不能按固定销量榜取商品；本周完成榜单工具接入及服务端联调，已验证模型能调用固定榜单；已部署 UAT，验收尚未完成，暂无线上收益数据。

- 反例：完成 MCP 开发和联调，效果很好，已上线并提升选品转化。
- 问题：没有说明新增能力，混淆 UAT 与生产上线，并添加未经验证的收益。

**对应成稿**

- **模型训练：** 针对原有 Prompt 方案容易遗漏复杂工具调用条件的问题，完成首轮 SFT 训练，用于改善工具调用规划；当前待离线评估，尚未上线。
- **MCP 开发：** 针对原有语义搜索无法按销量榜取商品的问题，完成榜单工具接入及服务端联调，模型已可调用固定榜单满足畅销商品查询需求；当前已部署 UAT，待验收。

实际交付只输出所需项目条目，不保留上面的素材、反例和讲解。

**目标前置与细节取舍**

当工作用途不能从名称直接看出时，按内容组织中的信息顺序规则前置目标，让读者先理解价值，再了解本周增量。例如：

- 反例：打通工具端与 Agent 端的来源记录，列出各类工具、字段、去重与缓存处理，最后才说明“支持后验训练分析”，并补充合入分支。
- 正例：**商品召回归因：** 为后验训练提供商品来源依据，完成工具端与 Agent 端的召回归因，保留同一商品跨工具、跨查询的来源信息。

**仅更新状态**

背景已在前序周报说明，本周素材只有“榜单工具测试通过，待发布窗口”。可直接写：

- **MCP 开发：** 榜单工具已测试通过，待发布窗口。

**存在交付依赖**

素材明确“工具已上线，但 Agent 尚未完成接入；等待服务端确认接口字段”。可写：

- **MCP 开发：** 榜单工具已上线，Agent 接入仍待服务端确认接口字段。

## 成稿检查

回读条目，确认 leader 能看懂本周动作、已有变化及当前状态，技术细节没有盖过业务用途，并按“结果与状态”回查素材。按用户指定范围核对数字、环境、依赖和定稿文字；信息足够时直接交付正文，不额外附写作分析。链接来源按[材料整合](content-organization.md#2-材料整合)查阅，缺失素材按前述取材规则处理。
