# 禁用表达细则

依据原始《行文组织风格.md》§5.1、§5.3、§5.5、§5.6 整理。用词禁令和元话语要求分别由主文件的“用语规范”“元话语”维护。

## 1. 对比与排比

### 适用条件

正在撰写或改写相关论述时适用；不为套用正例而给本来无需比较的内容新增对立对象。

### 规则与禁用内容

直接说明对象的性质、差异及依据，把对比放进实际推理中。禁止“不是 A，而是 B”“与其说 A，不如说 B”及“并非 A，而是 B”“不在 A，而在 B”等同类句式。禁止用连续重复的句型和三连排比制造节奏。

需要纠正误解时，分别交代原有理解、实际情况与判断依据；不要只替换连接词，保留原来的机械句模。

### 为什么这样要求

这类句式容易让表达围绕刻意设置的对立展开，并通过重复句型制造力度。读者需要理解的是具体差异以及差异成立的原因，固定句模本身不能提供这些信息。

### 正反例

以下为沿用原文句式类型的简化示例：

| 反例 | 正例 |
|---|---|
| 这套方案不是离线处理，而是在线处理。 | 这套方案采用在线处理。 |
| 与其说这是一份部署指南，不如说这是一份故障排查手册。 | 这份手册侧重故障排查。 |
| 它不是只记录错误，而是记录全部请求；它不是只保存状态，而是保存完整输入；它不是只显示结果，而是支持重新执行。 | 系统记录全部请求及其完整输入，并支持重新执行请求。 |

原文中的推进方式示例：

> 然而上述梯度并不合理，因为每个动作的梯度都共享了全局的回报 R(τ) 作为系数……因此更合理的做法是为每个动作计算相应的梯度系数。

该例通过原因和解决办法承接判断。改写时须有材料支持这些关系，不能为串联句子而添加因果。

## 2. 术语注释

### 适用条件

当前术语对目标读者陌生，且不解释会妨碍此次理解或判断时，才补充释义；仅在本篇首次出现不等于读者不认识它。重复与无关释义的禁令适用于已有注释。

### 规则与禁用内容

术语是否需要解释，以“目标与受众”确定的读者背景为准，不预设所有读者都熟悉业务或领域知识。对理解当前内容所必需的陌生术语，在首次出现时用简短中文解释其含义或用途；只有后文需要反复指代或消歧时，才补充英文全称及缩写。已有统一规范或用户已确认熟悉的缩写、指标顺序和记法，直接使用，不额外标注全称、逐项名称或顺序说明；只有采用非标准定义、存在实际歧义或读者确实陌生时才解释。括号不承担大段解释，之后保持称呼一致。禁止给普通或非核心名词逐个添加英文、重复释义，禁止反复解释已经引入的缩写。

### 为什么这样要求

没有信息增量的注释会频繁打断阅读。是否解释取决于读者是否需要借此理解或区分概念，不能仅因为一个词属于术语，就给它加上括号。

### 正反例

- 反例：`专家（expert）通过门控（gating）参与计算，并使用负载均衡（load balancing）机制。`
- 正例：`专家通过门控参与计算，并使用负载均衡机制。`
- 反例：在正文或表头写“标准答案（Gold）”，给含义已经清楚的中文名称重复添加英文。
- 正例：直接写“标准答案”；确需辨认生成来源时可写“标准答案（GPT-5.5）”，括号只保留有信息增量的来源名称。
- 反例：`GSB 为 0 / 10 / 1（Good / Same / Bad）`，在已有统一顺序的指标后重复标注名称。
- 正例：`GSB 为 0 / 10 / 1。` GSB 默认按 Good、Same、Bad 顺序书写，无需额外展开；同类已有统一规范的指标记法也遵循此规则。比较对象与方向仍按实际需要交代。
- 需要注释的正例：`研究者开始考虑通过强化微调（Reinforcement Fine-tuning，RFT）适配下游任务。` 后文直接使用 `RFT`，不重复解释。
- 新人文档反例：直接要求“创建 PPE 后验证改动”，没有说明 PPE 的用途，却给“任务”“代码”等普通词逐个补上英文。
- 新人文档正例：`先创建个人 PPE 泳道，用于独立测试相关功能。` 用途已清楚时，无需再堆叠英文全称。

## 3. 主语与指代

### 适用条件

“写出我们”只针对带读者进行推导或讲解的句子。操作步骤、字段标签和简短状态项不需要逐条增加“我们”；指代清楚的要求仍适用于相应正文。

### 规则与禁用内容

带读者进行回顾、展开、考虑、总结、发现等动作时，明确写出“我们”，不要为了简洁省掉讲解句的主语；描述模型或其他对象的动作时，写清实际执行者。禁止使用来历不明或指向不清的“它／其”。

### 为什么这样要求

省略讲解主语容易让语气变成突兀的指令；指代不明则会使读者无法判断动作由谁完成。需要明确区分作者与读者正在进行的推导，以及被介绍的对象实际执行的操作。

### 正反例

以下正反例取自原文：

- 反例：`先回顾一下 GRPO 的目标函数长什么样。对一组采样回答里的每个 token，它都要算一个比值。`
- 正例：`我们先来回顾一下 GRPO 目标函数的形式。对于一组采样回答中的每个 token，我们都需要计算一个比值。`

## 4. 结尾评价

### 适用条件

当前任务确需撰写总结或评价时适用；不要求每篇周报、PRD 或短文都新增总结和升华段。

### 规则与禁用内容

总结应落在前文已经说明的具体机制、结果或影响上。禁止通过“它真正值得记住的不在 X，而在于……”“这提醒了我们一件常被忽略的事……”等句式强行拔高，禁止在缺少依据时引出宏大原则或说教。

### 为什么这样要求

这类表达往往没有增加具体见解，却把局部发现扩大成普遍判断。原文允许的简短主观评论，如“原文写的是真好”，不等同于强行推导宏大结论。

### 正反例

以下正反例取自原文：

- 反例：`笔者认为，它真正值得记住的地方并不在公式有多复杂，而在于它提醒了一件常被忽略的事：当一个方法在小规模上好用、放大后却频频出问题时，与其堆补丁，不如先回头问一句，我们是不是在错误的尺度上做了某个本该在另一个尺度上完成的操作。`
- 正例：`正是这一处改动，让重要性采样、clip 和 reward 处在同一个尺度上，有效缓解了大模型 RL 训练不稳定的问题。`

正例中的机制和效果必须已有材料支持，不能为了删除空泛结论而自行补充。固定对比句式的形式要求见“对比与排比”；本条只处理结论是否有实质内容和相应依据。
