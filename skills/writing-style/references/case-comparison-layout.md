# 完整案例对比表

本节使用构造的商品问答说明两列表格，适合资料丰富、回答较长的模型案例对比。Case 1 材质依据、Case 2 推荐判断、Case 3 卖点提炼可采用相同布局。

## 适用场景

- 同一案例已有两组可比较的完整回答，读者需要结合问题和来源资料判断差异。
- 来源包含标题、描述、原文与翻译等多项内容，逐项横向设列会挤压回答宽度。
- 案例资料直接支撑当前论据，需要与分析就近放置。

简短回答可用“问题／对照组／实验组”三列；汇总指标、接口字段、GSB 分布沿用各自表格。没有翻译、商品描述或其他资料时省略相应行，不为套模板新增内容。背景资料区供读者核对依据，并不表示两组模型接收了完全相同的输入；输入差异按原始材料说明。

## 布局与阅读顺序

每个案例采用“简短标题 → 差异分析 → 完整案例表”。标题按主文件的命名规则标识案例与分析重点，例如“Case 1 材质依据”；分析直接说明两组回答的区别与依据，不逐句复述表格。

表格始终只有两个基础列，内部按信息用途分成上下两部分：

1. **上方资料区：** 第一行“案例资料”横向合并两列；用户问题也横向合并，只出现一次。标题、描述等有原文与翻译时，左列原文、右列中文，同类资料占同一行，单元格内用加粗标签区分用途。
2. **下方回答区：** 单独设置“控制组／实验组”表头，两组完整回答并排、顶端对齐。各案例的左右顺序保持一致，名称沿用实际分组。

以下是布局模板，花括号表示待填入的完整源内容，仅供说明结构；实际文档不能保留占位文字。

```html
<table>
  <tr><th colspan="2">案例资料</th></tr>
  <tr><td colspan="2"><b>用户问题</b><br>{完整问题}</td></tr>
  <tr>
    <td><b>商品标题（原文）</b><br>{完整原文}</td>
    <td><b>商品标题（中文）</b><br>{已有中文翻译}</td>
  </tr>
  <tr>
    <td><b>商品描述（原文）</b><br>{保留完整内容，按原有要点列出}</td>
    <td><b>商品描述（中文）</b><br>{保留完整翻译，按对应要点列出}</td>
  </tr>
  <tr><th>控制组</th><th>实验组</th></tr>
  <tr><td>{完整回答与局部差异高亮}</td><td>{完整回答与局部差异高亮}</td></tr>
</table>
```

这段 HTML 只说明布局。实际飞书组件语法与写入操作按 `lark-doc` 执行。

## 具体案例与排版要求

构造的 Case 1 问题是“Is this backpack suitable for a day hike?”。资料标题为“Lightweight Daypack”，描述为“Made of ripstop nylon with an adjustable chest strap”，并保留中文翻译；下方并排放两组完整回答。控制组只引用“lightweight”，实验组还引用“ripstop nylon”和“adjustable chest strap”。局部高亮这些差异后，读者可以直接对照上方资料核实材质与结构依据。

- **宽度：** 优先给两组回答相近、充足的宽度。本构造示例从七列改为两列；每列可从 460 px 开始按实际文档宽度调整，并通过预览核验，不作为所有表格的固定值。
- **表头：** 资料区和回答区表头使用公共规则规定的飞书中蓝色；普通资料与回答单元格保持无底色。这里是两列表格，不套用原生双栏组件的整栏背景要求。
- **单元格层次：** 描述中的并列要点用 bullet point 和一致的加粗标签。回答内部的大标题可改为正文大小的加粗标签，保留文字与层次，避免样本标题进入文档目录或字号压过案例标题。
- **差异高亮：** 保留来源和回答中的相关证据，只突出短语或关键判断；不整列铺色，也不把样本预测写成实际业务效果。
- **数据保真：** 完整问题、商品资料、翻译、回答及数字留在同一案例表中。不要为了缩短正文，用节选表替换后再把原始案例集中到文末。信息归属的公共边界见[结构化表格](information-presentation.md#2-结构化表格)。

## 为什么采用

原来的七列把问题、标题、翻译、描述、翻译和两组回答同时横排，导致长回答难读。两列布局让资料与回答依次展开，读者先了解依据，再直接比较两组回答；完整证据始终与分析相邻，无需跨章节查找。

- 反例：七列保持不变，只统一表头颜色，两组回答仍被挤在窄列里。
- 反例：正文仅保留短结论和回答节选，完整案例资料另设章节，再附跳转链接。
- 正例：同一张表上方集中共同资料，下方并列完整回答；通过合理列宽、单元格列表和局部高亮减少阅读负担。

## 完成核验

确认每个案例的分析与完整表格相邻；上方问题只出现一次、来源与翻译对应；下方两组回答完整且顺序一致；原始数字、内容与已有用户修改保留；合并行、列宽、表头颜色、段落层级和差异高亮已实际写入。不能仅以表格变短或写入成功判断完成，也不能把未做的视觉核验说成已完成。
