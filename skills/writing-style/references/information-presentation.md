# 信息呈现细则

在获准调整的内容中，先按当前信息关系选择形式，再读取对应小节。形式可以组合，例如在表格单元格内列点并强调关键结果。补充信息的取舍遵循[详略安排](content-organization.md#6-详略安排)。

配色与视觉基础规范由 [ui-standards](../../ui-standards/SKILL.md) 维护。实际编辑飞书时，按组件读取[飞书文档呈现](lark-presentation.md)，其中保留用户已确认的平台样式与操作核验。

| 当前信息关系或阅读用途 | 呈现形式与规则入口 |
|---|---|
| 连续解释或因果推导 | 正文段落 |
| 多个相对独立的并列要点 | [列表](#1-并列要点)；操作步骤按执行顺序编号 |
| 多个对象具有共同的比较或查阅维度 | [表格](#2-结构化表格) |
| 直接比较两份相对完整的内容，平台能清晰并排呈现 | [双栏](#3-双栏对照) |
| 优先注意具体词句或指标变化 | [视觉强调](#4-视觉强调) |
| 区分必要引文、短注释、延伸资料，或承载同一步骤的多个操作入口 | [引用块](#5-引用块) |
| 优先阅读简短、自足的结论或摘要，或用户指定某段使用 Callout | [高亮块](#6-高亮块) |
| 用图像说明主题，或用图示读清架构、流程、调用、分支、状态与层级关系 | 先查[可复用素材](#7-素材复用)，再按[图示方法](#10-架构与流程画板)组织 |
| 提供引用或资料入口 | [文档链接](#8-文档链接) |
| 比例、分式等数学关系用普通文字难以读清 | [公式与组件](#9-原生组件) |

精确数值查阅优先用表格，统计趋势按数据和图表能力选择载体。各形式按目标平台支持的能力实现。

## 1. 并列要点

**规则与禁用内容**

用 bullet point 分项表达同一主题下并列的问题、原因、措施、指标或资料。正文、表格单元格、引用块和高亮块内均采用相同规则；单元格内的独立指标也逐项列出。

需要展开解释的要点以“**简短标签：**”开头，随后说明具体情况、依据或影响。同一组同类条目的标签和格式保持一致，例如并列的“**类目划分：**”“**商品数量：**”，不要仅给第一项加标签。只有指标名称或简短资料条目时，直接逐项列出即可，不必为每项重复添加标签、冒号或解释。同一指标的名称与限定口径保留在同一条，不能为了列点拆散其含义。

每项围绕一个明确的点展开，同一问题的现象、原因和影响保留在该项中。标签应概括当前条目的职责、机制或关键变化，让读者仅扫描标签就能区分各项；避免只有“问题一”“问题二”等编号，也避免用“数据准备”“相关处理”等过于宽泛的名称掩盖本项要说明的具体变化。标签详略由当前比较维度决定，通用名称已足以定位时无需扩写。

条目内的信息按该条目的说明目的和职责归属组织，不因某句话提到同一节点，就把它放在该节点的任何条目下。决策条件和触发后的执行行为放在负责该决策的条目中；介绍输入压缩时，说明各环节的输入如何减少，区分匹配节点输入与后续模型输入。同一机制影响多个条目时，可分别说明与当前目的相关的行为或结果，不机械搬走所有相关事实，也不在两项重复整套执行说明。

标签属于正文，不增加目录层级，可以使用冒号。是否需要另起章节仍由“标题划分”决定。

**为什么这样要求**

分项和标签能直接呈现信息边界。读者可以先扫描要点，再阅读解释，减少自行从长段落或单元格中拆解和归纳的负担，同时避免增加过多章节标题。表格对齐对象与维度，列表区分维度内部的并列条目，两种形式可以同时使用。

**正反例**

以下例子根据参考文档中的“单轮 Planner 共训练”简化。

反例：此前主要依靠 Prompt 描述工具规则和业务约束，难以充分覆盖复杂约束与长尾意图，工具选择和参数生成的效果容易波动，同时规则增加使 Prompt 变长，为保证规划效果又使用了参数规模更大的模型，推理耗时较高。

正例：此前主要依靠 Prompt 描述工具规则和业务约束，存在两方面问题：

- **规划能力受限：** Prompt 难以充分覆盖复杂约束与长尾意图，工具选择和参数生成的效果容易波动。
- **推理时延较高：** 工具规则增加使 Prompt 变长；为保证规划效果而使用的较大模型，也增加了推理耗时。

单元格反例：在“主要指标”一格内写“发布电商视频作者渗透率；人均 Copilot 引导良好发文数”。

单元格正例：同一格内使用两个 bullet point：

- 发布电商视频作者渗透率
- 人均 Copilot 引导良好发文数

- 标签反例：条目介绍新增的榜单快照能力，却只用“**数据准备：**”命名，读者需要读完正文才能辨认处理对象。
- 标签正例：沿用用户修订的“**榜单快照准备：**”，正文说明它与画像并行读取。标签点明核心对象和职责，并行关系放在说明中，不为信息齐全把全部依赖塞进名称。
- 归属反例：在“**输入压缩：**”中写“只接收有效类目和相关画像；门控关闭时跳过该节点，不向 Planner 注入榜单类目信息”。后半句描述门控行为，与输入压缩不属同一说明目的。
- 归属正例：“**类目匹配门控：**”说明是否执行匹配及关闭后的跳过行为；“**输入压缩：**”既说明匹配节点只接收有效类目与相关画像，也说明不需要榜单的请求不再向 Planner 注入榜单类目信息，减少后续模型输入。前者交代执行控制，后者交代输入变化，不能因相关事实涉及同一门控机制就删去后一层影响。

## 2. 结构化表格

模型样本、对照案例、工具结构化输出、训练评估、数值精度及 GSB 结果的具体布局，按[表格场景与范例](table-examples.md)入口选择对应小节。

**规则与禁用内容**

用行区分对象，用列区分维度；层级、指标、适用范围、评分标准和权重等信息应各有清楚的位置。

中文说明文档的表头统一使用准确的中文业务名称，便于读者直接理解列的含义；ID、MCP 等通用缩写可保留。例如采用“榜单类型 ID”“榜单类型名称”“排序指标”，避免同一行混用“榜单”、`board_type_id`、`board_value` 这类不同命名方式。确需对照接口或底表时，在已有字段说明中保留准确映射；代码、Schema、数据字典的字段名及枚举值保留原文，不为中文化改写真实标识，也不无条件给每个表头追加英文。

较长的评分标准可以保留在单元格中，通过分段或列表组织内部层次，并为说明列分配足够宽度。单元格内有多个并列指标、条件或要点时，遵循“并列要点”规则列出，不以文字长短决定是否列点。不要因标准较长就退回多层嵌套列表，也不要为缩短表格而删去关键条件。

比较方向保持一致，列名明确对象和单位。表头文字统一左对齐，不随数据列改为居中或右对齐；数据区的数值右对齐，状态可居中，说明左对齐并顶端对齐。表头固定起点便于扫描列名，数据区按内容对齐便于比较；例如“控制组／实验组”表头左对齐，下方得分仍右对齐，避免把整列的对齐设置同时套到表头。平台不支持时优先保留清楚的行列对应。只有理解表格需要而上下文尚未交代时，才在表旁补充读表目的、来源、时间、口径或样本范围。表后解释影响判断的关键差异，不逐格复述。精度、差值和空值符号按[小数位与差值](table-examples.md#3-小数位与差值)处理，既有源值优先。

按信息归属组织内容，保持读者完成当前查阅所需的信息就近完整。已有表格中，定义、公式和规则属于某个比较对象或维度，且是理解该项所必需的内容时，保留在对应单元格内；长内容先用单元格内的 bullet point、加粗标签、原生公式和合理列宽改善排版。不能仅为缩短表格或降低单元格字数，就把内容抽到表外，让读者重新拼接对应关系。仅在用户明确要求拆分、内容是多个对象共用的说明，或属于非当前查阅必需的详细推导时，考虑单独组织，并在原处保留必要结论和明确指引。判断调整是否有效，要看读者能否就近理解该项、是否减少跨位置查找，不能只看表格是否变短。

支撑当前论据的案例资料属于正文证据，不能按外部 Wiki 或飞书参考文档的方式处理。评测案例的问题、商品资料、两组回答和差异分析应放在一起，让读者当场核对；不能仅为压缩正文，就用节选替换已有完整案例，再把完整资料集中到文末或另页，要求读者跳转。例：分析卖点如何改变推荐理由时，商品描述、翻译及模型回答就近并列，优先改善列宽、列表和局部高亮。用户明确要求节选或分离原始数据时，再按其范围调整。

工具目录、能力清单等按类别分组的表格，将同类条目相邻排列，纵向合并分类列中重复的单元格，每个类别只显示一次。对象名称、功能等明细仍各占一行，不合并不同对象的信息。

**为什么这样要求**

固定列让读者能沿同一维度比较不同对象，也能沿一行查全某个对象的信息。大量嵌套列表会反复出现字段名称，使读者需要上下寻找对应关系；表格将这些关系直接对齐。

分类单元格合并后，既减少重复标签，也明确标出一组条目的归属；无需再用成片底色重复表达同一分组关系。

**正反例**

反例：每个指标都使用一组多层 bullet point，分别列出层级、适用域、评分标准和权重；长评分标准再继续嵌套子列表，多个指标之间难以对照。

正例：将共同字段固定为列。以下构造两个文本处理指标，展示组织形式：

| 层级 | 指标 | 适用域 | 评分标准 | 权重 |
|---|---|---|---|---|
| 格式 | `format_pass` | 文本抽取 | 校验输出能否解析为 JSON，且包含规定的字段；此构造规则将格式不合格的样本单独列为无效样本，不纳入内容评分。 | 单独报告 |
| 内容 | `entity_precision` | 文本抽取 | 在格式合格的样本中，正确抽取的实体数除以全部抽取的实体数；没有抽取实体时记为 n/a，并单独报告此类样本数。 | 单独报告 |

更复杂的 Query 评分标准可以在对应单元格内按相关性、粒度、规范性和多样性分项，表格外层仍保留统一的指标结构。

- 分类反例：MCP 工具表在每行重复相同分类，读者需要自行识别分组。
- 分类正例：MCP 工具表保留“用途／MCP 工具名／功能”三列；选品工具连续排列，共用一个纵向合并的“选品”单元格，创作工具同样处理，名称和功能逐行对应。
- 单元格归属反例：为缩短榜单表格，把回购公式及其四项指标定义移到表后，回购榜单元格只剩“回购指数”。
- 单元格归属正例：回购公式和指标定义保留在回购榜的排序逻辑单元格内，定义用 bullet point 分项，标签加粗，读者在这一行即可理解计算口径。
- 方向反例：同一张表在不同指标行交换 Base 与 SFT 的位置，差值又未说明减法方向；读者无法沿列比较。
- 方向正例：各行保持“Base／SFT／变化”顺序，注明变化为 SFT 减 Base，数值按列对齐；只说明影响当前判断的差异。

## 3. 双栏对照

**规则与禁用内容**

双栏左侧放一个对象，右侧放另一个对象，分别保留完整的段落、代码或图示结构。例如对照组与实验组配置、修改前后的回答、两个方案的流程图或界面截图。

两侧使用明确、简短的标签，并在同一篇文档中保持对象的左右顺序一致。尽量按相同维度和顺序组织内容，让对应部分处于相近位置；公共背景放在双栏之前，共同的差异分析可放在之后，避免两侧重复说明。栏宽按内容需要分配，以文字、代码和图片清晰可读为准，不为并排而过度压缩内容。

**为什么这样要求**

将待比较内容放在相邻位置，可以减少上下滚动和记忆前文的负担。明确的标签和对应顺序帮助读者定位差异，同时保留每个对象完整的上下文。栏间留白进一步标明内容归属。

**正反例**

- 反例：先放完整的对照组配置，中间插入大段说明，后面再放实验组配置；读者需要反复上下翻找才能确认改了什么。
- 正例：左栏标注“**对照组**”并放置配置代码块，右栏标注“**实验组**”并放置相同字段顺序的配置代码块。构造示例中，两侧的 `include_summary` 分别为 `false` 和 `true`，对应字段并排呈现后，差异可以直接看到。

## 4. 视觉强调

**规则与禁用内容**

展示评估结果或指标时，选择对结论重要的结果或变化幅度进行局部强调。判断改善方向时结合指标含义，例如耗时降低也可以是正向结果。

同类信息的强调方式保持一致。保留对比起点、指标名称和必要口径，使重点能够被正确理解。不要整表、整段或所有数值同时加粗着色，也不要通过弱化重要负向结果来制造单向结论。颜色和加粗只改变视觉优先级，不提高事实强度；统计显著性仍需原始材料支持。

**为什么这样要求**

读者扫描结果时，需要快速识别关键变化。局部强调能降低寻找重点的成本；过多着色会削弱层次，脱离指标含义的配色则可能误导判断。

**正反例**

- 反例：将整个结果表统一着色并全部加粗，辅助数据与核心指标没有视觉区别。
- 正例：在构造的“模型 A 的准确率由 0.7000 提升至 **0.8400（+20.00%）**”中，仅强调加粗部分，保留起点和指标名称的普通样式。
## 5. 引用块

**规则与禁用内容**

引用块紧邻对应正文，用于区分引文、注释与资料。原文引用标明来源；转述按说明呈现，不伪装成逐字引文。

评估口径、例外条件等短注释以加粗的“注：”开头，后接普通正文；字段名、代码标识保留行内代码格式。已有准确标签如“评分说明：”可沿用。

同一步骤的多个操作入口在引用块中用列表排列，链接按“文档链接”处理。主论述及其必要前提保留在正文。

**为什么这样要求**

引用块能区分主论述和来源、注释，减少补充材料对阅读主线的干扰，并让读者知道哪些内容是在引用、哪些内容属于说明。

**正反例**

- 反例：在结果分析段落中连续插入来源、评分口径和链接，读者难以区分结果与补充说明。
- 注释正例：判定标准后紧接引用块：

> **注：** 在此构造的实体抽取评测中，只比较 `entities` 内的实体，`explanation` 不参与实体准确率；格式是否合格单独报告。

- 评分说明正例：用引用块区分结果与具体判分机制：

> **评分说明：** 此构造规则将无法解析的输出单独计为无效样本；实体准确率只统计格式合格的样本，同时报告无效样本数。

## 6. 高亮块

**规则与禁用内容**

高亮块内容简短、自足，直接给出结论和必要限定；详细论证保留在正文。

高亮块强调一组信息的阅读优先级，局部加粗与背景色强调具体词句或数值。不要让每段都有高亮块，不把整节内容搬进高亮块，也不使用“本文将介绍”等写作预告代替摘要。

**为什么这样要求**

读者可以先获取核心结果，再决定深入阅读哪些部分。高亮块过多或过长，会失去快速概览的作用。

**正反例**

- 反例：将完整的训练过程、全部评分指标和结果逐项复制进一个很长的 Callout，开头仍是“下面将介绍训练效果”。
- 构造正例：在高亮块中用“**结果摘要：**”引出两个 bullet point：
  - 模型 A 的准确率由 0.7000 提升至 0.8400（+20.00%）。
  - 同一测试环境中，解析步骤耗时由 2.4s 降至 1.8s。

分域得分、评分口径和分析保留在后续正文或表格中。高亮块内部同样遵循“并列要点”的规则。

## 7. 素材复用

**规则与禁用内容**

检查参考资料中的相关图像、架构图、界面截图和画板。已有素材能清楚解释当前主题、适合受众且内容口径明确时，优先直接复用到主文档，配合必要的文字说明。仅论文图片注明图源；其他素材不额外添加“图源”“截图来源”或“复用自某文档”等介绍。用于深入阅读的资料链接仍按正文需要保留。仅放参考链接不能代替正文所需的图示；不要因为正在重写文章，就默认所有图都要重新绘制。

复用时保留图片质量、必要的可编辑性及来源文档原貌。按正文需要调整展示尺寸和位置，保留必要图例、版本及规划项说明；来源图包含历史设计时，明确其与当前状态的关系，不把规划内容描述成已上线能力。若没有合适素材，或现有素材无法满足准确性与阅读要求，再补绘或改编。

**为什么这样要求**

参考资料中的图示往往已经整理了完整关系或真实界面，直接复用能减少重复制作和转述遗漏，也让正文与依据保持一致。图旁优先说明读者需要理解的内容，避免重复介绍内部素材的出处；论文图源则用于查证研究依据。素材是否适用取决于内容和受众，不能仅凭“自行绘制”或“来源现成”判断质量。

**正反例**

- 架构反例：参考 LR 已有清晰完整的架构画板，却另画一张信息更少的流程图，只在文末附上 LR 链接。
- 架构正例：在新人指南的架构部分复制 LR 2.0 的原生画板，说明图中规划项、历史节点的口径，再用正文解释新人需要理解的主流程，无需另写内部图源。
- 图源反例：在内部 App 截图旁写“截图来源：某 LR”，图注中又写“复用自某 LR”。
- 图源正例：内部截图仅标注“达人助手首页”；引用论文架构图时注明论文名称及链接。
- 界面反例：介绍 Agent 的使用形态时仅写文字，或重新制作示意界面，忽略参考资料中的真实 App 截图。
- 界面正例：直接复制 LR 2.0 的“达人助手”截图到体验部分，保留原图内容，调整显示尺寸，图注说明界面内容。


## 8. 文档链接

禁止用链接充当文档标题、章节标题或列表中的加粗要点标签，也禁止通过给链接加粗来模拟标题。标题和标签使用无链接的文本，引用放在后面的说明句或资料入口中。看板、代码仓库等非飞书文档网页仍可使用普通文字超链接。

将标题标签与引用入口分开，能帮助读者区分内容层次和资料入口。飞书原生引用及保存后核验见[平台引用规则](lark-presentation.md#4-原生引用)。

**正反例**

- 标题反例：`**[GPU 看板](URL)：**查看模型服务的 GPU 使用情况。`
- 标题正例：`**GPU 资源：**通过 [GPU 看板](URL) 查看模型服务的 GPU 使用情况。`

## 9. 原生组件

比例、分式等数学关系用普通文字难以读清时，用公式呈现；简单加减或普通定义用自然文字。公式使用清楚的短名称，完整限定条件紧邻公式；原属表格的公式与口径保留在同一单元格。代码格式用于代码和标识。

选择目标格式支持的组件，保留信息关系和可读性。飞书的原生公式、组件操作与保存核验见[平台组件规则](lark-presentation.md#6-原生组件与公式)。

## 10. 架构与流程画板

本节说明通用图示方法。飞书原生画板的创建、插入及预览核验见[平台画板规则](lark-presentation.md#8-画板创建与核验)。

**规则与禁用内容**

- **信息选择：** 一张图解释一个主要关系，只保留示意图、节点名称和必要的分组、连线、分支短标签。宏观架构图优先呈现核心职责和运行边界，关键配置、鉴权及主要交付按本次关注点保留；输入构建、缓存、水位、重试等内部步骤仅在需要判断这些机制时展开，不因实现中存在就默认入图。图内不放整句的描述性标题、解释段落或底部说明；必要解释放在相邻正文，正文已有时不重复添加。不能把整句说明拆成多行或塞进节点来规避。节点和连线以当前材料为依据，明确方向及必要分支；不能为凑出完整架构编造模块、调用或因果。关系缺少依据时保留不确定性。多个独立问题可分图，避免压成一张难读的大图。
- **布局与配色：** 主流程方向一致，同类节点尺寸、对齐和间距统一，合并不影响理解的中间状态，避免大面积空洞和不必要的绕行。优先通过布局实现直线连接；分支标签绑定连线，节点标签放在节点内，不用游离文本框补充说明。按数据、决策、执行和结果等实际职责区分协调的配色，同类保持一致；不将所有节点铺成同一种颜色，也不为增加颜色任意拆分职责。
- **插入位置：** 放在首次需要理解该关系的对应章节，通常位于简短概述之后、逐模块或分支细节之前；前后方案比较图靠近方案比较段。图示替代重复的关系描述，正文保留必要结论、限制和精确数据，不逐节点复述；不将所有图统一堆到文末，也不移动未获准修改的定稿内容。
**为什么这样要求**

图示让读者直接看到文字中分散的连接、层级和分支；插在对应论述旁可以减少往返查找。

**正反例**

| 当前内容 | 正例 | 反例与问题 |
|---|---|---|
| 架构材料已明确请求入口、Planner、执行器、工具及返回路径 | 在架构概述后生成调用关系画板，标清方向，随后说明关键模块职责 | 只写“此处建议放架构图”，未生成和插入，读者仍需自行拼接关系 |
| 审核流程存在通过、驳回、修改后重提三个分支 | 在流程概述后插入分支画板，展示回到哪一步；操作入口仍放在对应步骤中 | 把各段原文逐句装进矩形，连线不标条件，无法看清分支 |
| 两个方案的调用路径不同，需要读者比较 | 并排画出两条路径，沿用相同模块名称，突出实际变化，放在方案比较段旁 | 两图名称和方向不一致，使排版变化被误认为架构变化 |
| 画板展示预取与类目匹配的调用关系 | 只画节点、连线及“并行”“enabled / disabled”等短标签，解释放在正文 | 在图顶写“当前链路：类目匹配位于父图等待路径”，图底再写“意图返回时，模型可能已经发出”，让画板重复承担正文说明 |
| 周报只有“架构方案已评审，待开发” | 保留简短进度说明 | 因出现“架构”就补画缺少依据的系统图，扩大范围并引入虚构信息 |
