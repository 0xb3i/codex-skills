# 架构与废弃路径审查

重构 / 审查模式还要完成以下扫描：

- 画清入口、核心流程、依赖方向和职责边界，识别主模块膨胀、跨层访问、循环依赖及可内聚拆分的职责。
- 搜索无调用或不可达代码、已被新实现取代的旧路径、重复实现、失效 feature flag / 配置 / 兼容层、只服务旧行为的测试与注释。
- 检查临时 `print` / `console`、调试开关、绕过分支、一次性脚本、注释掉的实验代码和伪成功逻辑；不要把正常的结构化日志、诊断能力误判为临时代码。
- 扫描临时脚本、备份副本、旧补丁、一次性导出、Agent 草稿及构建或验证留下的中间产物。删除前确认其未被代码、配置、构建、测试或文档引用，且不属于用户工作文件、必要 fixture 或约定交付物；不能仅凭扩展名、命名或未跟踪状态判定可删。
- 删除前核对静态引用、动态注册、配置、序列化协议、构建入口和运行时调用；不能仅因“不熟悉”就判定代码废弃。
